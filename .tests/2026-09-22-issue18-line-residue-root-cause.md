日期：2026-09-22 晚 · 结论：**非保存/持久化代码缺陷，为测试流程反复覆盖设备配置所致**。

## 只读取证（2026-09-22 晚）

- GET /config：`{"x1":0.379,"y1":0.499,"x2":0.619,"y2":0.499,...}`（= 最后一次自动化写入值）。
- 全新加载页面渲染坐标：0.379 / 0.499 / 0.619 —— 与服务器逐位一致，读取/渲染链路诚实。

## 已确认的真实缺陷（均已修复）

1. 「重置」产生退化线草稿，固件拒绝无线配置（`invalid_config`）→ 死路；已改为 reset-to-saved。
2. 编辑时双线渲染造成「多出一根黄线」；已改为单线草稿预览。
3. 设备存在 60s+ 的 401/超时波窗口，保存会间歇失败（toast 已显示真实原因）。

## 流程禁令（即刻生效）

自动化真机流程 **禁止对设备配置做任何写入**（包括"验证性"保存与恢复性写入）；行为验证只允许只读 GET/渲染比对，或由用户本人操作。

## 补充取证（2026-09-22 18:00）：为什么修复"始终不生效"——设备 HTTP 缓存策略

| 证据 | 值 |
|---|---|
| `/` 响应头 | `Cache-Control: max-age=86400, public` + `ETag "3f94a132"` |
| 含义 | 浏览器 24 小时内不向设备索要新 index.html，一直运行缓存里的旧 JS |
| 旧 hash 资源回退 | `GET /assets/index-BeDhHToU.js`（已不存在的版本）→ **HTTP 200 + index.html 内容**（SPA fallback），非 404 |
| 当前服务器真实版本 | `index-OeUYPgvI.js`（= HEAD d4aed88a 构建） |
| 当前 canonical 线 | `0.379→0.619 @ 0.499`（最后一次自动化冒烟线，水平） |

**机制**：每次 web 重烧后，用户浏览器在最长 24h 内继续运行旧版 JS（含已修复的 bug）。
今天固件未动、web 推送 6 个版本，用户浏览器多数时间运行的是旧构建 → 用户看到/测到的
是旧 bug（双线、保存失败等），与已推送修复脱节 → 表现为"反复修不好"。

**修复归属**：需要固件静态服务对 `index.html` 下发 `Cache-Control: no-cache`（hash 资源可继续长缓存）
→ 固件域，本轮未动，建议独立 Issue。
**用户侧即时规避**：强刷（Cmd+Shift+R）/ DevTools Disable cache，即可加载当前版本。
