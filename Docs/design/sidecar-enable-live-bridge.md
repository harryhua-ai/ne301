# Sidecar Enable and Live Production Bridge

## Scope and authority

This bridge is the Host-owned Web projection layer only. The native v4 control core, NFC4 enable linearization, floor precommit, ENR1 receipt proof, and LVN4 live ingest/read remain the AppHost implementations delivered by Host #104/#113/#91; this card modifies none of them. The bridge consumes their public C entry points from the Web API module and projects them onto the frozen `ne301.sidecar.bridge.v1` typed ops. It creates no v5 wire, no new browser capability, and no native control authority. `report-policy.read` and `report-policy.apply` stay `UNAVAILABLE` with reason `CAPABILITY_NOT_REVIEWED`, and `video.open`/`video.close` keep their existing gated behavior.

## Enable read

`enable.read` requires the current trusted Sidecar descriptor, an active control session bound to the grant's session generation, and native capability bit 8. It reads the last trusted App snapshot through the control core and projects the App-owned observable business state (`status.state` `running`/`stopped`) onto the accepted App #32 payload shape `{session_generation, value}` with exactly those two keys. A missing snapshot, a non-running/non-stopped state, or a stale session generation yields `UNAVAILABLE`/`ENABLE_STATE_UNKNOWN`; a failed snapshot read yields `UNKNOWN`. The browser never carries enable authority; it only sees the projection.

## Enable apply

`enable.apply` is a dangerous write. The request must carry `session_generation` equal to the grant's native session generation and a boolean `value` (true = Enabled, false = Paused). The Host derives `expected_state_revision` from the last trusted snapshot (`REJECTED`/`STATE_REVISION_UNKNOWN` when none exists; zero is never guessed) and `expected_config_generation` from the trusted known config generation (`REJECTED`/`CONFIG_GENERATION_UNKNOWN` when unknown). The one-shot admin confirm token bound to the grant and op (same bearer flow as `counters.reset`, issued only to the trusted admin host page, never forwarded in App-visible payloads) is consumed before registration; without it the bridge returns `REJECTED`/`ADMIN_CONFIRM_REQUIRED`.

The bridge then builds the exact 16-byte `ENB1` payload (magic, desired state, expected state revision, zero reserved) and registers `ENABLE_SET` with the native control core. Only a native `APPLIED` command state — which the core grants exclusively after the durable floor precommit for Paused, the App CAS commit, an exact readback, and the ENR1 receipt proof — is reported to the browser as `APPLIED` with payload `{session_generation, value}`. Stale config and state conflicts map to `CONFLICT`; invalid/resource rejections map to `REJECTED`; storage I/O/unknown outcomes and timeouts map to `UNKNOWN`. Nothing is optimistically applied. Monotonic request IDs are enforced by the native core and surface as `REJECTED`/`DUPLICATE_ID_CONFLICT`.

## Live subscribe

`live.subscribe` requires the stream name `live`, an active control session with native capability bit 9, and a live module bound to the same session generation, publisher, app, SPKI SHA-256, and native TBS as the grant; otherwise `UNAVAILABLE`/`LIVE_UNAVAILABLE`. The first subscribe primes the per-grant read cursor at the newest retained event so old window facts are never replayed as fresh. Each call (App subscribe or broker poll) returns the trusted bounded view: session and view epochs, freshness (`fresh`/`stale`/`none`) with age, continuity state, `through_seq`, `source_total`, `source_gap`, `host_dropped_events`, packet counters, `loss_unknown`, `resync_required`, `tracks_truncated`, `next_cursor`, the configured target class from the trusted snapshot (`unknown` when absent), up to 16 track records with q16 points, and up to 32 cursor-tagged events. The read cursor advances only across returned events; native gap detection against the retained ring stays authoritative. More than 16 native tracks sets `tracks_truncated` and emits only the bounded prefix — a partial view is never presented as a complete replacement.

`live.unsubscribe` requires the same stream name, clears the per-grant subscription, and answers `APPLIED` with `{active: false}`. Grant revocation, expiry, package/identity/generation changes, and sidecar deactivation clear the subscription through the existing slot revocation path.

## Broker pump and App #32 contract

The host broker starts a poll loop only after an `APPLIED` live.subscribe result and stops it on unsubscribe, revoke, or terminal stream status. Polls are broker-internal HTTP bridge calls whose request IDs occupy the reserved high range `[0x80000000+1, 0x80000000+0x07ffffff]`, disjoint from App-allocated request IDs. Each poll result is validated and projected into strict App #32 EVENT frames on stream `live` with a broker-local monotonic `stream_seq`: `{server_now_ms, events?}` with `{sequence, timestamp_ms, track_id, direction, target_class}`, and `{server_now_ms, tracks?}` with q16 points scaled to the App's 0..1000 space and zero-point tracks filtered. A new source gap, host drop increase, `loss_unknown`, `resync_required`, or `tracks_truncated` emits status `GAP`; staleness or data disappearance emits `STALE`; freshness `none` before the first frame posts nothing (the App keeps its "not yet received" state). Any status terminates the pump so lost facts are never redrawn as continuous; recovery requires a fresh grant. The one-shot dangerous-confirm EVENT is not injected while the live pump is active, because the accepted consumer validates every EVENT as live data; the armed token still applies to the next matching op.

## Tests and evidence

- `tests/web_sidecar_bridge` drives the real bridge module with the real control core (v4 session, fake precommit/receipt proofs) and the real live module: 1175 checks, 0 failures, covering enable read states, the v3/no-bit8 gate, confirm gating, the exact NFC4/ENB1 wire bytes, duplicate-ID rejection, applied/stale/storage receipt mapping, live unavailability gates, cursor priming and advancement, freshness aging, gap watermarks, track projection, and 17-track truncation.
- `Web/src/test/appManagement/sidecarBridgeLive.test.ts` covers the broker pump: strict App frame shapes, high-range poll IDs, quiet-frame suppression, staleness/loss/gap/truncation fail-closed behavior, unsubscribe and revocation teardown, malformed-view STALE handling, and confirm arming without live-frame contamination.
- `tests/sidecar_host_bridge` runs the real signed App #32 bundle in Chrome against the mirrored host server: enable read projection, confirm-gated apply with token-leak checks, live EVENT consumption in the Realtime UI, GAP fail-closed, and live-unavailable surfacing.

NOT_RUN on this card: real-device media authorization, device camera/network paths, production signing keys, real tracker producer feed (App #27 on hardware), and final release packaging.
