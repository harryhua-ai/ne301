# App Management Run Once eligibility

Issue #39 uses a conservative eligibility rule for the v1 Run Once action because `GET /api/v1/app/installed` does not report an ABI or compatibility profile.

The UI offers Run Once only when both conditions hold:

- No business UI is registered for the committed app ID.
- The committed record's `package_sha256` exactly matches a known signed v1 fixture package digest.

The current allowlist contains one digest: `f98811f8f5eab265ad9e0df532bf71b1e54bdb2b8cc111866c2c4c87f1b7dcd8`, for `HELLO_V1_PACKAGE` in `tests/app_installer/installer_vectors.h`. The vector is generated by `tests/app_installer/sign_packages.py`; hashing the checked-in package bytes confirms this value. Checked-in negative vectors remain ineligible even though their app ID is also `hello-app`: business version 2.0.0 `HELLO_V2_PACKAGE` (`2a86a2982c042385850daac8962b3cef1d49f838e03a503032b0c6a5874a644f`), `HELLO_V2_ALT_PACKAGE` (`c431baf86273a18554db312d804f27b46a0d83052c14241cf918507a0eef27c0`), `HELLO_V2_HISIG_PACKAGE` (`d803bfe64a59f39b3472ef6af1c29e85fa98a6634246460db3466e38fa641a02`), and the ABI-mismatch `HELLO_BADABI_PACKAGE` (`ea23ec9425cf19aafe6dedde29be72b7e49cd97a3c50a90593e5500e31aac1b5`).

The API's `package_sha256` is SHA-256 over the complete signed package bytes. `app_installer.c` computes it from the submitted package and `api_app_install_module.c` returns the bytes as lowercase hexadecimal. The separate `tbs_sha256` covers the signed-to-be-executed portion and is not used for fixture matching.

App ID and business package version do not prove ABI compatibility. Any missing, unknown, or different package digest fails closed and the Run Once section is not rendered. If the installed-app protocol later exposes a current compatibility profile tied to the committed package identity and digest, replace this fixture allowlist with that protocol evidence.
