# Offline App Platform Integration Evidence

This task creates a repeatable software-only acceptance record for the already merged Host and App work. It does not satisfy device, production signing, release, or user acceptance gates.

## Run

From the NE301 repository root:

```sh
python3 tests/app-platform-offline/run.py
```

The runner first checks that each participating test directory has no existing build outputs that its legacy `clean` target would remove. It generates the requested FSBL `1.0.3.1` and STEdgeAI `3.0.0` version headers in a temporary directory, exposes that directory through `CPATH` for host compilation, and runs the existing C/API suites. It then removes build outputs generated by this run. It disables Python bytecode output and does not write generated headers into `Custom/**` or `FSBL/**`.

The App #25 artifact and the #99 origin-study input are the same 422,963-byte NEUI file. The runner extracts the signed asset with the existing #99 Node source audit, then independently verifies the same bytes with the merged Host `app_sidecar_verify_bundle()` C function. The test pins the public `test-publisher` SPKI, manifest native TBS binding and signed UI TBS recorded by the artifact. A separate assertion reads the current compiled Host native trust anchor and reports the cross-root result.

The C suites compile and exercise the merged Host implementation and Web API modules. Memory-backed storage, fake flash, session/device seams, and network transport seams simulate hardware-facing boundaries. They do not turn those boundaries into device observations. The installer and lifecycle suites include a fake external purge callback; #88/#101 report purge integration remains `BLOCKED/NOT_AVAILABLE`.

The runner audits the historical #99 Chrome source and asset inputs but does not start Chrome. The previous Chrome measurements are recorded in [the merged origin study](../sidecar-origin-signed-browser-study.md). The current Chrome rerun and all device actions remain `NOT_RUN`.

## Suite map

| Suite | Merged Host modules exercised | Reusable evidence and boundary |
|---|---|---|
| `tests/app_admission` | Admission, trust anchor, v1/v2/v3 package checks, admission Web API | Signature, identity, version, ABI and package rejection paths; generated vectors use existing development/test keys. |
| `tests/app_installer` | Installer, storage adapter, state store, install Web API | Install/update/conflict/fault and API behavior over simulated I/O; not physical storage or the real report purge. |
| `tests/app_host_run` | Host run gate, installer, admission and state | Run eligibility and recovery behavior against fixture storage. |
| `tests/app_host_session` | Host session, control, state, report service, device session seam | Session and control behavior under a pthread-backed device shim. |
| `tests/app_host_control` | Host control and control Web API | Authenticated/unauthenticated and session control API behavior against test request contexts. |
| `tests/app_sidecar` | Incremental NEUI verifier | Signature, identity, ABI, asset, malformed package and callback-boundary cases. |
| `tests/app-platform-offline` | Exact App #25 signed asset plus current Host verifier and anchor | Exact bundle/TBS/SPKI/ABI/version verification and explicit native-root mismatch. |
| `tests/app_sidecar_lifecycle` | Sidecar lifecycle and installer coordination | Staged/ACTIVE/revoke, boot recovery and fault paths over a memory backend; purge callback is fake. |
| `tests/app_state` | Durable app state store | State recovery, corrupted data and injected I/O failures against test storage. |
| `tests/app_report` | Existing report service | Report service lifecycle and queue behavior from merged #44/#75; not the unfinished #88 policy or #101 purge integration. |
| `tests/storage_gate` | Storage media gate, NVS session, admin auth and Web API integration | UNKNOWN/untrusted media, refused destructive writes, recovery and authentication boundaries against fake flash/NVS. |
